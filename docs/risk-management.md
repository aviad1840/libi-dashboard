# LIBI — תוכנית ניהול סיכונים

על-פי דרישת הקול קורא + **המדריך לשימוש אחראי ב-AI במגזר הציבורי** של מערך הדיגיטל הלאומי.

**גרסה:** 0.9 (טיוטה) · **תאריך:** מאי 2026 · **בעלי תפקיד:** RACI ב-§7.

---

## 1. עקרון מנחה

המערכת היא **תמיכת החלטה (decision support)** ולא תחליף לגורם מקצועי. שום פעולה שמשפיעה על אזרח לא מתבצעת ללא אישור מלווה/עו"ס. זוהי החלטה ארכיטקטונית, לא רק מדיניות — ה-UI אוכף זאת.

## 2. ‎6 דומיינים לפי המדריך

### 2.1 פרטיות

| סיכון | חומרה | סבירות | בקרה |
|--------|--------|---------|------|
| דליפת PII דרך LLM external | קריטי | נמוך (LLM private) | private endpoint על נימבוס + PII redaction + audit |
| גישה לא מורשית של מתאמת לתיק | גבוה | בינוני | RBAC + ABAC ברמת רשומה + audit log |
| איסוף מידע מעבר ל-purpose | בינוני | נמוך | data minimization בכל endpoint + DPIA רבעוני |
| Re-identification מאגרגציה | בינוני | נמוך | k-anonymity בדוחות (k≥5) |

### 2.2 סייבר

| סיכון | חומרה | בקרה |
|--------|--------|------|
| Prompt injection | גבוה | prompt firewall + input sanitization + LLM output validation |
| חציית ENV/secrets | גבוה | Nimbus Key Vault · אין secrets ב-code |
| DDoS | בינוני | Rate limiting · Cloudflare-equivalent על נימבוס |
| Supply chain | בינוני | dependency scanning · automated CVE alerts |

### 2.3 הוגנות (Fairness)

| סיכון | חומרה | בקרה |
|--------|--------|------|
| הטיה דמוגרפית בהמלצות | גבוה | בדיקת disparate impact רבעונית על פני: גיל, מגדר, ארץ מוצא, יישוב |
| Underserved populations | גבוה | KPI מיוחד למיעוטים · התרעה אם זיהוי נופל מתחת לרף |
| Feedback loop bias | בינוני | counterfactual analysis · ספקים חדשים מקבלים "exploration boost" |

**תהליך**: בדיקת הוגנות רבעונית מתועדת. תוצאה חורגת → halt + תיקון.

### 2.4 שקיפות והסבריות

| סיכון | חומרה | בקרה |
|--------|--------|------|
| Black box | גבוה | מודלים heuristic + linear עד שיש ROI ל-deep learning |
| חוסר אמון של מתאמת | גבוה | UI מציג את 6-12 הסיבות שתרמו לכל ציון |
| חוסר ידע על שינויי מודל | בינוני | model versioning · changelog נגיש למתאמות |

**תהליך**: לכל מודל יש model card פומבית לוועדה (פיצ׳רים, בסיס אימון, ביצועים, מגבלות).

### 2.5 בקרה אנושית

| סיכון | חומרה | בקרה |
|--------|--------|------|
| auto-approve פעולה | קריטי | לא קיים. UI מונע. |
| התעלמות מהמלצה ללא תיעוד | נמוך | "סיבת דחייה" חובה אם מתאמת דוחה Top-1 |
| בקרת איכות על המתאמת | נמוך | דגימה אקראית של ‎5% מההחלטות לסקירה |

### 2.6 יכולת ערעור (Right to Appeal)

| מנגנון | תיאור |
|---------|--------|
| כפתור "ערעור" | בכל המלצה. פותח תיקון ידני + מועבר לעו"ס בכיר |
| תיעוד | כל ערעור נשמר. שיעור הצלחה מדווח רבעונית |
| אגרגציה | אם > 15% ערעורים על מודל מסוים → חקירה ופוטנציאל retrain |

## 3. Gate Reviews

לוח **Data & Responsible AI Review** — לא ועדה קבועה. נדרשת רק ב:

| Trigger | פאנל | החלטה |
|---------|------|--------|
| מקור דאטה חדש | משפטית · פרטיות · סייבר · דאטה | אישור / דחייה / תנאי |
| מודל AI חדש או שדרוג עיקרי | דאטה · ‎AI · אתיקה · משתמש | אישור deploy |
| Rollout לאתר חדש | פיתוח · מבצעי | אישור |

## 4. Off-Switches

| Off-switch | תכליל |
|------------|---------|
| Per-model | להעביר מודל מסוים ל-rule-based fallback |
| Per-feature | לכבות שכבת AI שלמה |
| Per-region | לעצור Rollout לעיר ספציפית |
| Full system | חזרה ל-mode ידני מלא (מצב חירום) |
