# רוטין: curator - לולאת למידה, אחת לשלושה ימים

**זה לא הרוטין השבועי.** הרוטין השבועי (`curator-weekly.md`) מכייל מקורות ותדירות.
**הרוטין הזה עונה על שאלה אחרת: מה אביעד באמת עשה בשלושת הימים האחרונים,
ומה זה אומר על היעדים ועל מה שכדאי לפרסם.**

**למה זה קיים:** המערכת רואה רק מה שנדחף אליה. היא לא רואה את השיחות ואת העבודה
בפועל. הלולאה הזו סוגרת את הפער בעקיפין - דרך העקבות שהעבודה משאירה ב-git ו-`inbox/`.
**זה תחליף חלקי, לא מושלם. תגיד את זה בדוח כשאין די אותות.**

## שלב 1 - אתחול. הרץ את שלוש השורות האלה בדיוק, בלי לשנות:

```bash
git fetch origin --prune -q
for r in origin/main origin/claude/autonomous-workers-routine-hna6je; do git cat-file -e "$r:aviad-desk/scripts/desk.sh" 2>/dev/null && git checkout "$r" -- aviad-desk/scripts/ && break; done
bash aviad-desk/scripts/desk.sh start curator
```

הפקודה נכשלה - **עצור, דווח, אל תתקן ידנית ואל תמשיך לעבוד.**

ארבעה מקורות, בסדר הזה:

2. **`inbox/`** - כל מה שאביעד דחף ידנית. **זה האות החזק ביותר כשהוא קיים**
3. **`feedback/queue/*.jsonl`** - פידבק מטלגרם מהתקופה
4. **`state/runs.jsonl`** - אילו סוכנים רצו, מה הפיקו, ומי החזיר דוח ריק פעמיים ברצף
5. **`inbox/published/`** - מה אביעד באמת פרסם. **האות החזק ביותר על הקול שלו**,
   ומעובד בנפרד בשלב 4.5

## שלב 4 - ההמרה. זה הלב של הרוטין

לכל אות משמעותי, ענה על ארבע השאלות **בכתב**:

```
מה אביעד עשה:      [שורה אחת עובדתית מהראיה]
לאיזו טענה זה נוגע: C<n> - ואיך. אין קשר לאף טענה - כתוב "אין", זו תשובה תקינה
לאיזה יעד זה מקדם: ציר 1 (כוח מוסדי) / ציר 2 (הישגים מדידים) / ציר 3 (מיצוב חיצוני)
                    לפי positioning.md. או "לא מקדם אף ציר"
מה הצעד הבא:       פעולה אחת קונקרטית, או "אין"
```

**שתי בדיקות חובה:**

- **נקודת הוכחה חדשה?** אם נוצר תוצר שמוכיח טענה - הצע רשומה ל-`proof-points.md`
  **בפורמט המלא, כולל "מה זה לא מוכיח".** אתה מציע בלבד, לא כותב לשם
- **חומר לפרסום?** אם יש כאן מהלך שמפעיל 2+ מנועים מ-`publishing-playbook.md` -
  ציין איזה מנועים, ולמה זה עומד בסף. **אל תכתוב את הפוסט. זה תפקיד amplifier**

## שלב 4.5 - לולאת הטיוטה. **חובה, וזה השלב שהכי משנה לטווח ארוך**

```bash
python3 aviad-desk/scripts/diff_learn.py --auto
```

הכלי מזווג לבד כל טיוטה מ-`amplify/` לנוסח שאביעד באמת פרסם ב-`inbox/published/`,
ומחלץ את ההבדל. **זה המקום היחיד שבו המערכת לומדת לכתוב בקול שלו במקום לנחש אותו.**

`"אין זוג חדש לעיבוד"` - זו תשובה תקינה. אביעד לא פרסם מאז. עבור הלאה.

יש פלט - קרא אותו והפעל שיקול דעת בשתי נקודות:

1. **`הסיר מספרים`** - זה לא סגנון, זה חשד לכשל ראיה. בדוק ב-`amplify/` אם למספר
   שאביעד מחק היה מקור. לא היה - **זה ממצא AP10 וצריך להיכנס לדוח כדגל**, לא כלקח סגנון
2. **`תחנת X חסרה בטיוטות שלך`** - זה כן סגנון, וזה הלקח הכי שימושי ל-`amplifier`

ואז:

```bash
python3 aviad-desk/scripts/diff_learn.py --rules
```

**כלל בשל = חזר שלוש פעמים.** כל כלל בשל שעוד לא נמצא ב-`context/voice-learned.md`:
הצע אותו בדוח תחת "מועמדים לכלל", **ואל תכתוב אותו לקובץ בעצמך.**
המסלול הוא הצעה -> אישור של אביעד בטלגרם -> כתיבה. כמו כל שינוי הקשר אחר.

**אין כלל בשל - אל תמציא אחד.** שתי חזרות אינן כלל, וכתיבת כלל מוקדם מלמדת את
`amplifier` לחקות מקרה יחיד. זה גרוע מלא ללמוד כלום.

## שלב 5 - כתיבת התוצר

`aviad-desk/curator/learning-{DATE}.md`:

```
# לולאת למידה - {DATE}

## מה אביעד עסק בו (עובדתי, מהראיה בלבד)
## המרה ליעדים - טבלת ארבע השאלות
## מועמד לנקודת הוכחה חדשה
## מועמד לפרסום - איזה מנועים ולמה
## לולאת הטיוטה
   כמה זוגות עובדו, מה חזר, ומה בשל לכלל. אין זוגות - כתוב "אביעד לא פרסם מטיוטה מאז"
## מועמדים לכלל ב-voice-learned.md
   רק כללים בשלים (3 חזרות). אין - כתוב "אין". אל תציע כלל משתי חזרות
## מה המערכת פספסה
   נושא שאביעד עסק בו והמערכת לא העלתה מעצמה. זה הפער האמיתי.
## אותות חלשים
   מה לא הספיק לקביעה. אל תמתח מסקנה מאות בודד.
```

**חוק הברזל של curator חל גם כאן: שינוי ללא ראיה גרוע מאי-שינוי.**
שלושה ימים זה חלון קצר. **"אין די אותות" היא תשובה תקינה ולעיתים הנכונה.**
אל תמציא מסקנה כדי למלא סעיף.
